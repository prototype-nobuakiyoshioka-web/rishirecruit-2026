# Phase 4 - Task 08: フッター再設計(最小限の情報パネル化)

**目的:** Task 06-07で実装した「4セクション構成のフルフッター + フェード連動」を全面的に作り直す。新しい設計では、フッターは**最小限の情報パネル**(役場情報・法的リンク・著作権のみ)とし、ページ(トップ/他)とデバイス(PC/SP)で異なる表示パターンを持つ。

**これは修正ではなく再設計です。** 既存の `Footer.tsx` の中身は大きく作り替えることになります。

---

## コンテキスト

### なぜ作り直すのか(経緯)

Task 06-07 で実装した「4セクション構成のフルフッター + position: fixed によるフェード連動」を実機(Playwright + 目視)で確認したところ、以下の問題が見つかった:

1. フッターの不透明な背景が3D Canvasの手前を完全に覆い、島が見えなくなる
2. 一度 `opacity: 1` になったフッターが、スクロールを巻き戻しても**消えない**(片道のみの状態管理になっていた)
3. フッター表示エリアと3Dマップエリアでスクロール操作の挙動が分断され、UXとして破綻していた

これらの問題を踏まえ、フッターの設計思想そのものを「ページ末尾の大きなセクション」から「**Header・ColumnBoardと同様のコンパクトな情報パネル**」に変更した。

| ページ | PC | SP(モバイル) |

### 1. `store/scroll-progress-store.ts` の修正(双方向対応)

Task 07で実装した状態管理を確認し、**スクロールを巻き戻した時に表示フラグが `false` に戻る**ことを保証する。

- 現状の実装(`isRotationComplete` フラグ、または `markRotationComplete`/`resetRotationComplete` のようなアクション設計)を確認すること
- もし「一度 true になったら戻さない」前提の実装になっていた場合、双方向(行き/戻り)で正しく追従するように修正する
- `IslandModel.tsx` 側の `useFrame` 内の判定ロジックも合わせて確認し、毎フレームの判定で「現在の状態」を正しく反映するよう修正する(片道のrefガードが残っていれば削除・修正)

### 2. `components/layout/Footer.tsx` の全面作り直し

**責務:** 役場情報・法的リンク・著作権のみを表示する最小限のコンポーネント。トップページ/他ページ、PC/SPで表示方法を出し分ける。

実装内容:
- `"use client"` 必須(`usePathname`, Zustandストアの購読のため)
- 掲載内容は前述の「掲載内容」セクションの通り(役場情報・プライバシーポリシー・利用規約・著作権表記のみ)
- `usePathname` でトップページ(`/`)かどうかを判定
- レスポンシブ判定(PC/SP)の実装方法はCodexの判断に委ねるが、Tailwindのブレークポイント(`md:` 等、Header.tsxで使用したものと一貫させる)を使うことを推奨
- **PC×トップページ**: 専用パネルとして、Header下〜ColumnBoard上のエリアに配置。`opacity` をストアの状態に連動。背景は半透明 or 控えめなものにする
- **PC×他ページ**: 通常の `<footer>` 要素として、ページ最下部に静的配置(`opacity: 1` 固定)
- **SP(トップ/他ページ問わず)**: このコンポーネント自体はページ内に何も描画しない(`null` を返す、または `hidden md:block` 的なクラスで非表示にする)。SP版の中身は次項の `Header.tsx` 側で扱う

**参照モード**(このとおりでなくてOK、より良いパターンがあれば提案してください):

```tsx
"use client";
import { usePathname } from "next/navigation";
import { useScrollProgressStore } from "@/store/scroll-progress-store";
import Link from "next/link";

function FooterContent() {
  return (
    <>
      <address>
        利尻富士町役場<br />
        〒097-0101<br />
        北海道利尻郡利尻富士町鴛泊富士野6<br />
        Tel: 0163-82-1111<br />
        Fax: 0163-82-1253
      </address>
      <nav>
        <Link href="/privacy">プライバシーポリシー</Link>
        <Link href="/terms">利用規約</Link>
      </nav>
      <p>© 2026 rishirecruit ・ 利尻富士町</p>
    </>
  );
}

export function Footer() {
  const pathname = usePathname();
  const isRotationComplete = useScrollProgressStore((s) => s.isRotationComplete);
  const isTopPage = pathname === "/";

  // SP は Header 側のハンバーガーメニューで表示するため、ここでは描画しない
  // (md: 以上でのみ表示する想定)

  if (isTopPage) {
    return (
      <footer
        aria-hidden={!isRotationComplete}
        className="hidden md:block fixed ... [専用エリアの位置指定]"
        style={{
          opacity: isRotationComplete ? 1 : 0,
          pointerEvents: isRotationComplete ? "auto" : "none",
          transition: "opacity 600ms ease",
        }}
      >
        <FooterContent />
      </footer>
    );
  }

  return (
    <footer className="hidden md:block ...">
      <FooterContent />
    </footer>
  );
}
```

`isRotationComplete` の値が双方向(true⇔false)に正しく追従することが、このコンポーネントが正常動作するための前提条件。

### 3. `components/layout/Header.tsx` の更新(SP版ハンバーガーメニューへの統合)

**変更内容:**
- 既存のハンバーガーメニュー(Task 04実装、ナビ6項目)に、フッター情報(役場情報・法的リンク・著作権表記)を追加する
- ナビ項目とフッター情報は視覚的に区別がつくよう、区切り線(`<hr>` 等)や異なるタイポグラフィスケール(フッター情報はやや小さめの文字等)を用いることを推奨
- このセクションは**トップページ・他ページ問わず共通**で表示する(ハンバーガーメニューはページに関わらず同じ構成)
- Header.tsx 内に直接フッター情報を書いてもよいし、`Footer.tsx` から共有可能な形でコンテンツ部分(役場情報等)をエクスポートして再利用してもよい(重複を避けたい場合)。設計判断はCodexに委ねるが、**情報の重複管理(2箇所に同じ住所等をハードコードする)は避けること**

### 4. デザイントークンの適用

`docs/04-design-tokens.md` を参照し、以下を意識して適用する:

| 用途 | 候補トークン |
|---|---|
| トップページ専用パネルの背景 | **半透明**にすること(例: `--c-deep-ocean` を `rgba()` で透過させる、または `--c-paper` の半透明版)。3D島が透けて見える程度の不透明度を目指す |
| 他ページの通常フッター背景 | 不透明でよい(`--c-deep-ocean` 等) |
| テキスト色 | 背景とのコントラストを確保(`--c-text-inverse` 等) |
| 角丸・シャドウ | Header・ColumnBoardとは異なる、控えめな表現でよい(過度に装飾的にしない) |

### 5. アクセシビリティ対応

- トップページ専用パネルが非表示(`opacity: 0`)の間、`aria-hidden="true"` と `pointer-events: none` を設定(Task 07の実装を踏襲)
- 表示後(`opacity: 1`)は `aria-hidden` を外し、操作可能にする
- `<address>` タグを役場情報に使用(セマンティックHTML)
- ハンバーガーメニュー内のフッター情報も、キーボード操作・スクリーンリーダーで問題なくアクセスできること

## 完了後の確認手順

1. `npm run dev` を起動
2. **トップページ・PC幅**: `http://localhost:3000` を開き、初期状態でパネルが非表示であることを確認
3. スクロールし、95%地点でパネルがふわっとフェードインすることを確認。**3D島が透けて見える**(完全に隠れない)ことを確認
4. **スクロールを上に戻し**、パネルが再び非表示になることを確認(最重要、Task 07のバグ再発確認)
5. パネル表示中も3Dマップ部分でスクロール操作ができることを確認(エリア分断がないか)
6. ブラウザ幅をモバイル幅に縮小し、トップページでパネルが表示されない(ページ内に存在しない)ことを確認
7. ハンバーガーメニューを開き、ナビ6項目の下に役場情報・法的リンク・著作権が表示されることを確認
8. PC幅のまま、存在しないURL(例: `/jobs`)にアクセスし、404ページの最下部に通常のフッター(役場情報等)が常時表示されることを確認
