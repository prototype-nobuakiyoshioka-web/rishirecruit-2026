# Phase 4 - Task 05: コラム看板(HUD要素)実装

**目的:** トップページ(`/`)限定で、画面左下に常時表示される「コラム看板」を実装する。木製看板風のイラスト + テキストを持つ独立したHUD要素で、クリックすると `/columns` へ遷移する。3D Canvasの回転・スクロールとは完全に独立して、画面に固定表示される。

### Task 04(ヘッダー)からの教訓

前回のレビューで、「指示した角丸・背景色・余白が実装に反映されていない」という見た目の不具合が発生し、差し戻しが発生した。今回は同じ轍を踏まないため、以下を徹底すること:

- **独立したコンテナとして実装する**(背景・パディング・角丸・シャドウを持つ1つの要素としてまとめる、テキストや図形がバラバラに浮いた状態にしない)
- 見た目に関わるプロパティ(背景色・角丸・余白・シャドウ)は**該当のCSS変数を実際に適用したことをコード上で確認できる形にする**(コメントで「ここで何のトークンを使ったか」を明記すると良い)

## やってほしいこと

### 1. `components/scene/ColumnBoard.tsx` の新規作成

**責務:** 木製看板風のHUD要素。クリックで `/columns` へ遷移する。

実装内容:
- `"use client"` 必須
- **独立したコンテナ**(div等)としてまとめ、その中にイラスト表現 + テキストを配置
- 木製看板の見た目表現:
  - 背景: 木目を感じさせる暖色(茶色系)。デザイントークンに直接「木の色」は無いため、`docs/04-design-tokens.md` のアクセントカラーやペーパー系トークンから最も近いものを選び、コメントで選定理由を書く。または、木の質感はSVGまたはCSSグラデーションで簡易的に表現してよい
  - 看板の「脚」や「杭」のような視覚要素(完全な作り込みは不要、シンプルなCSS図形やSVGで雰囲気を出す程度でよい)
- テキスト: 「コラム」+「NOTE」の2行、または「コラム(NOTE)」の1行(レイアウトに応じて判断してよい)
- `position: fixed` で画面左下に配置(画面に対して固定、3D Canvasの動きと無関係)
- z-index を Header と衝突しない適切な値に設定(Header より低くてよいが、3D Canvasよりは確実に手前)
- クリックハンドラで `/columns` へ遷移(Next.js の `Link` コンポーネントでラップするか、`useRouter` の `push` を使う)
- ホバー時に何らかの視覚フィードバック(わずかな拡大・影の変化等)があるとUXとして良い(必須ではない)

**参照モード**(このとおりでなくてOK、より良いパターンがあれば提案してください):

```tsx
"use client";
import Link from "next/link";

export function ColumnBoard() {
  return (
    <Link
      href="/columns"
      aria-label="コラム一覧を見る"
      className="fixed bottom-6 left-6 z-40 ..."
    >
      <div className="..." /* 木製看板風コンテナ: 背景・角丸・シャドウ・パディング */>
        <span className="...">コラム</span>
        <span className="...">(NOTE)</span>
      </div>
    </Link>
  );
}
```

実際のスタイル値(色・サイズ・形状)は Codex の判断で具体化してよいが、**「木製看板に見える」という見た目の意図が伝わるレベル**まで作り込むこと(単なる四角いボタンにしない)。

### 2. トップページ限定表示の実装

`ColumnBoard` は**トップページ(`/`)でのみ表示**し、他のページ(`/jobs`, `/message` 等、まだページ自体は存在しないが将来的に)では表示されないようにする。

実装方法の選択肢(Codexの判断で選んでよい):
- **方針A(推奨)**: `app/page.tsx`(トップページ専用)に直接 `ColumnBoard` を配置する。`app/layout.tsx`(全ページ共通)には置かない
- 方針B: `usePathname` で現在のパスを判定し、`/` の時のみ描画する条件分岐をコンポーネント内に持たせる

方針Aの方がシンプルで意図が明確なため推奨だが、最終判断はCodexに委ねる。選んだ方針をコミットメッセージに明記すること。

### 3. デザイントークンの適用

`docs/04-design-tokens.md` から、以下を参考に具体的なトークンを選定して適用する:

| 用途 | 候補トークン |
|---|---|
| 看板の背景色(木製感) | アクセントカラー系から最も近いものを選定(コメントで選定理由を明記) |
| テキスト色 | `--c-text-primary` または白文字(背景とのコントラスト次第で判断) |
| 角丸 | `--radius-md` 〜 `--radius-lg` 程度(看板の角は完全な四角でも丸みがあってもよいが、極端なカプセル型にはしない、ヘッダーと差別化する) |
| シャドウ | `--shadow-md` または `--shadow-pop-md`(「押せる感」を出したい場合はpop系を検討) |
| 余白 | `--space-*` シリーズ |

Header(Task 04)とは異なる視覚的役割(「カプセル型の上品なナビ」 vs 「木製の素朴な看板」)を意識し、トーンを書き分けること。

### 4. アクセシビリティ対応

- `aria-label="コラム一覧を見る"` 等、スクリーンリーダー向けのラベルを設定
- キーボード操作(Tab移動・Enterで遷移)が可能なこと(`Link` コンポーネントを使えば標準対応される)
- 十分なクリック領域を確保(モバイルでもタップしやすいサイズ)

## 制約・前提

- `"use client"` を `ColumnBoard.tsx` の先頭に書く
- `ColumnBoard` は3D Canvas(`IslandCanvas`)の**外側**(独立したDOM要素)として実装する(3Dシーンの一部ではない、Task 04のHeaderと同じ設計思想)
- リンク先 `/columns` は現時点でまだページが存在しない可能性が高いが、リンクは正しく張ること(404になるのは想定内)
- TypeScript の型エラーを出さない(`any` 禁止)
- Next.js の `Link` コンポーネントを使う(`<a>` タグの直書きは避ける)
- 既存の Task 04(Header)・Task 02(スクロール回転)の実装に影響を与えない

## 完了後の確認手順

1. `npm run dev` を起動
2. `http://localhost:3000` をブラウザで開く
3. 画面左下に木製看板風のUI要素が表示されていることを確認(単なる四角ボタンになっていないか目視確認)
4. スクロールしても看板が画面左下に留まり続けることを確認
5. 3D島をスクロールで回転させても、看板の見た目・位置に変化がないことを確認
6. 看板をクリックし、URLが `/columns` に遷移しようとすることを確認(404で構わない)
7. キーボードの Tab キーで看板にフォーカスが当たり、Enter で遷移できることを確認
8. ブラウザの開発者ツールでモバイル幅に切り替え、看板が画面内に収まり、タップしやすいサイズであることを確認
9. Header(Task 04)の見た目・動作に影響がないことを確認
10. `npm run build` でビルドエラーがないことを確認
