# Phase 5 Task 11: 島サイズの自動フィット実装

## 目的

島のバウンディングボックスから実サイズを取得し、
画面幅に応じてカメラ距離を自動計算することで、
どの画面サイズでも島が適切に収まるようにする。

## 実装内容

### 実装1: バウンディングボックスによる自動フィット

#### 仕組み
GLBメッシュのバウンディングボックスから島の実サイズを取得
const box = new THREE.Box3().setFromObject(mesh);
const size = box.getSize(new THREE.Vector3());
島を画面に収めるのに必要なカメラ距離を計算
垂直方向: distance = (size.y / 2) / Math.tan(fovRad / 2)
水平方向: distance = (size.x / 2) / (Math.tan(fovRad / 2) * aspect)
→ 大きい方を採用する
マージン係数をかけて余白を確保
finalDistance = distance * marginFactor

#### マージン係数

| デバイス | マージン係数 | 意図 |
|---|---|---|
| SP(md未満) | 画面幅から左右8pxずつの余白 | 島を最大限大きく表示 |
| PC(md以上) | 現状の見た目を維持する値 | 変更しない |

**SP時の要件**:
- 島の横幅が「画面幅 - 16px(左右8pxずつ)」に収まる
- つまりほぼ画面いっぱいに島を表示する
- 島の上下は見切れないこと

#### 実装場所

`components/scene/IslandModel.tsx` または
`components/scene/IslandCanvas.tsx` に実装する。

バウンディングボックスの取得は GLB ロード後に行う必要があるため、
`useGLTF` の結果を使って `useMemo` で計算する。

画面幅の取得とリサイズ対応も実装すること。

#### 注意点

- `useFrame` 内で毎フレーム計算しない(useMemo でキャッシュ)
- リサイズ時のみ再計算する
- **PC時の見た目を1pxも変えないこと**
  (自動計算の結果が現在の値と一致するようマージン係数を調整するか、
   PC時は従来の固定値を使う分岐にする)

### 実装2: SP時の島を12px上に移動

Task 10 で島を下げたが、12px分だけ上に戻す。

投影後の見た目で約12px上になるよう調整すること。

### 変更してはいけないファイル
- 上記以外すべて

- 島全体が画面内に収まる(見切れない)
- 島がコラム看板・カード領域と重ならない
- スクロール連動回転の挙動を維持する
- `useFrame` 内で重い計算をしない

## セルフ検証

### 1. バウンディングボックスの取得確認

一時的にログを出力し、以下を確認:
- 取得できた島のサイズ(x / y / z)
- 計算されたカメラ距離
- 各画面幅での実際の適用値

確認後、ログは削除すること。

### 2. SP時の島の幅測定

390×844 と 375×667 で島の描画幅を測定し、
「画面幅 - 16px」に近い値になっているか確認する。

| 画面幅 | 期待する島の幅 | 実測値 |
|---|---|---|
| 390px | 374px | ? |
| 375px | 359px | ? |

### 3. 収まりの確認
- 島の上端・下端が見切れていないか
- コラム看板と重なっていないか
- カード領域と重なっていないか

### 4. リサイズ追従の確認
ブラウザ幅を段階的に変えて、
島のサイズが追従するか確認する。

### 5. PC非デグレ確認
1440×900 で Task 10 完了時点と完全に同一か、
スクリーンショットを比較して確認する。
