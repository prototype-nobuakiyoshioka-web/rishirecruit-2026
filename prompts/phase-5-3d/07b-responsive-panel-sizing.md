# Phase 5 Task 07b: サイドパネルのビューポート適応

## 背景と目的

エリア情報パネルとタブスライダーを縦に並べた結果、
画面下部でスライダーが見切れる問題が発生している。

固定の rem 値でパネル高さを組んでいるため、
ビューポート高さが変わると破綻する。

**目的:** どのビューポート高さでも2つのパネルが
画面内に収まり、内容が読める状態にする。

## 要求仕様

### 必須要件

1. 2つのパネル(AreaInfoPanel + AreaPostSlider)が
   常にビューポート内に収まること
2. Header と重ならないこと
3. 画面下端に適切な余白が残ること
4. 短い画面(例: 700px高)でも内容が読めること
5. 3Dマップの操作を妨げないこと(pointer-events)

### 推奨する実装アプローチ

以下を組み合わせて解決してください。
どれをどう使うかは実装者の判断に委ねます。

| 手法 | 用途 |
|---|---|
| `dvh` 単位 | モバイルのURLバー伸縮に対応した実高さ |
| `clamp()` | フォントサイズ・余白の可変化 |
| `minmax()` / `flex` | パネル間の高さ配分 |
| `min-height: 0` | flex子要素のはみ出し防止 |
| `overflow-y: auto` | 内容が入りきらない場合のスクロール |
| `container queries` | パネル幅に応じた内部レイアウト調整(任意) |

### 具体的な検討事項

- ラッパーの高さを `calc(100dvh - ヘッダー高さ - 上下余白)` で確定させる
- 2つのパネルの高さ配分を決める
  (例: 情報パネルは内容に応じて可変、スライダーは残り全部)
- フォントサイズを `clamp(最小, 可変, 最大)` にして
  小さい画面では自動的に縮小させる
- 画像領域も `aspect-ratio` や `clamp()` で可変にする
- それでも入りきらない場合の逃げ道
  (パネル内スクロール or 内容の省略)を用意する

## 制約

- 変更してよいファイル:
  - components/scene/AreaSidePanels.tsx
  - components/scene/AreaInfoPanel.tsx
  - components/scene/AreaPostSlider.tsx
  - app/globals.css(CSS変数の追加が必要な場合のみ)
- 変更してはいけないファイル:
  - IslandCanvas.tsx / IslandModel.tsx / Pin.tsx / Background.tsx
  - Header.tsx / Footer.tsx / ColumnBoard.tsx
  - store/scroll-progress-store.ts
- エリア自動切替(activeAreaSlug 連動)の挙動は維持する
- WordPress側ファイルは変更しない

## 受け入れ条件

以下すべてを満たすこと:

- [ ] ブラウザ高さ 1080px で2パネルが収まる
- [ ] ブラウザ高さ 800px で2パネルが収まる
- [ ] ブラウザ高さ 700px で2パネルが収まる
- [ ] いずれの高さでもタブ(Job/Event/Spot)が見える
- [ ] いずれの高さでもスライドのナビ(← ・・ →)が見える
- [ ] Header と重ならない
- [ ] スクロールでエリアが切り替わり、両パネルが更新される
- [ ] 3Dマップのドラッグ操作ができる

3. 見切れ・重なりがないか目視する

問題があれば報告前に修正してください。
