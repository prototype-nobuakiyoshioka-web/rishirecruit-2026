# Phase 5 Task 08: モバイルレイアウト対応

## 背景と目的

現在、AreaInfoPanel と AreaPostSlider は
`hidden md:block` によりモバイルで非表示になっている。

モバイルでも同等の情報を提供できるレイアウトを実装する。

## 設計方針

PCと同じ構成(エリア情報 → タブスライダーの縦積み)を
モバイル向けに圧縮して画面下部に配置する。

### レイアウト構造

┌─────────────────┐
│ Header(既存) │
├─────────────────┤
│ │
│ 3D島 │ ← 画面上部〜中央
│ │
│ │
│ [看板] │ ← 左下
│ ┌─────────┐│
│ │エリア情報 ││ ← 右寄り、幅85%程度
│ └─────────┘│
│ ┌───┬───┬───┐ │
│ │Job│Evt│Spt│ │ ← タブ
│ ├───┴───┴───┤ │
│ │ スライダー │ │ ← ほぼ全幅
│ └────────────┘ │
└─────────────────┘


### 要求仕様

| 項目 | 要求 |
|---|---|
| 表示 | md未満でも AreaInfoPanel / AreaPostSlider を表示する |
| 配置 | 画面下部に縦積み、下端に適切な余白 |
| 幅 | エリア情報は画面幅の80〜85%程度、右寄せ |
| 幅 | スライダーは画面幅の90〜95%程度 |
| 高さ | 2パネル合計で画面高さの50〜60%以内に収める |
| 文字 | clamp() で可変。SPでも読める最小サイズを確保 |
| 画像 | スライダー内の画像はSPでは小さくするか非表示も検討 |
| 3D | 島の表示領域を上部に確保する(パネルで潰さない) |
| 操作 | 3Dマップのタッチ操作を妨げない |

### エリア情報パネルの圧縮方針

SPでは説明文が長いと高さを圧迫するため、以下のいずれかで対応:

- 説明文のフォントサイズを小さくする
- 行数を制限する(line-clamp)
- キャッチコピーのみ表示し説明文は省略する

どれを採用するかは実装者の判断に委ねます。
読みやすさと省スペースのバランスを取ってください。

### スライダーの圧縮方針

SPでは横並び(テキスト+画像)が窮屈になる可能性があるため:

- 画像を小さくする
- 画像を上、テキストを下の縦積みにする
- 画像を非表示にする

いずれかを選択してください。

### カメラ設定について

SPでは画面が縦長になるため、現在のPC向けカメラ設定
(position: [-6, 5, 12], fov: 55)では島が
見切れる可能性があります。

必要に応じて、画面幅に応じたカメラ設定の出し分けを
検討してください(任意。まずレイアウトを優先)。

## 制約

### 変更してよいファイル
- components/scene/AreaSidePanels.tsx
- components/scene/AreaInfoPanel.tsx
- components/scene/AreaPostSlider.tsx
- components/scene/ColumnBoard.tsx(SP時の位置調整が必要な場合のみ)
- app/globals.css(CSS変数追加が必要な場合のみ)

### 変更してはいけないファイル
- IslandModel.tsx / Pin.tsx / Background.tsx
- Header.tsx / Footer.tsx
- store/scroll-progress-store.ts
- WordPress側ファイル全て

### 維持すべき挙動
- スクロールでの島の回転
- スクロールでのエリア自動切替(activeAreaSlug 連動)
- PC表示のレイアウト(デグレさせない)
