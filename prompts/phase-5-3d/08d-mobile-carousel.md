# Phase 5 Task 08d: SP版を横スクロールカルーセルに変更

## 背景

Task 08c でSP対応は成功したが、
エリア情報パネルとスライダーが縦積みのため
画面の6割以上を占め、主役である3D島が見えなくなっている。

## 目的

SPにおいて、島の表示領域を確保しつつ
エリア情報と投稿情報にアクセスできるレイアウトにする。

## 設計方針

参考サイト(haru-ni.net のSP版)と同様の
**横スクロールカルーセル**を採用する。

### 変更前(現状)

┌─────────────┐
│ 3D島(小) │
├─────────────┤
│ エリア情報 │ ← 縦積みで
├─────────────┤ 高さを圧迫
│ タブ+スライダー│
└─────────────┘


### 変更後(目標)

┌─────────────┐
│ │
│ 3D島(大) │ ← 画面の65〜70%
│ │
│ [看板] │
├─────────────┤
│ ← カード → │ ← 横スクロール
└─────────────┘ 高さ25〜30%

## 要求仕様(SP時のみ)

### レイアウト

| 項目 | 要件 |
|---|---|
| カード領域の高さ | 画面高さの25〜30%以内 |
| カードの並び | 横方向、スワイプでスクロール |
| カード幅 | 画面幅の80〜85%(次のカードが少し見える) |
| カード間隔 | 12〜16px |
| スクロール | CSS scroll-snap でカード単位に吸着 |
| 3D島の領域 | 画面高さの65〜70%を確保 |

### カードの内容構成

横に並べるカードの順序:

1. **エリア情報カード**(1枚目)
   - Area ラベル
   - エリア名 + ローマ字
   - キャッチコピー
   - 説明文(行数制限あり)

2. **投稿カード**(2枚目以降)
   - タブ(Job/Event/Spot)による絞り込みは維持
   - 1投稿 = 1カード
   - タイトル・サムネイル・「詳細を見る →」

### タブの扱い

現在のタブ(Job/Event/Spot)は維持するが、
カルーセルの上部に横並びで配置する。

タブを切り替えると、カルーセルの
2枚目以降(投稿カード)が入れ替わる。

### 3D島のカメラ調整

SPでは画面が縦長のため、島が見切れないよう
カメラ設定をSP用に出し分けることを検討する。

- 現在のPC設定: position: [-6, 5, 12], fov: 55
- SP用の調整案: fov を広げる、または z を大きくして引く
- 島が画面上部65〜70%の領域に収まるようにする

※ IslandCanvas.tsx の変更が必要になるが、
　**PC時の値は絶対に変えないこと**。
　画面幅で分岐させて、SP時のみ別の値を使う。

## 制約

### 変更してよいファイル
- components/scene/AreaSidePanels.tsx
- components/scene/AreaInfoPanel.tsx
- components/scene/AreaPostSlider.tsx
- components/scene/IslandCanvas.tsx(SP用カメラ設定の分岐のみ)
- components/scene/ColumnBoard.tsx(位置調整が必要な場合のみ)

### 変更してはいけないファイル
- app/globals.css
- IslandModel.tsx / Pin.tsx / Background.tsx
- Header.tsx / Footer.tsx
- store/scroll-progress-store.ts
- WordPress側ファイル全て

### 絶対に守ること
- **PC(md以上)の見た目を1pxも変えない**
- fixed 要素の位置指定プロパティを auto にしない
- 親の幅が未確定な状態で子に width: 100% を使わない
- エリア自動切替(activeAreaSlug 連動)の挙動を維持する
