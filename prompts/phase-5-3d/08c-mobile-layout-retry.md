# Phase 5 Task 08c: モバイルレイアウト対応(再実装)

## 前回の失敗と学び

Task 08 では以下の理由でレイアウトが崩壊した:

1. fixed 要素の `top` / `right` を auto にする、または
   inline style から外部CSSへ移管した
   → 基準点が消え、要素が左上に落ちた
2. 親の幅が未確定な状態で子に `width: 100%` を適用した
   → 幅が0近くに潰れ、日本語が1文字ずつ折り返された

**今回の絶対条件: PC(md以上)の既存実装には一切触らない。**

## 設計方針

PCとSPで**別々のスタイルを持たせる**。共通化しない。

| ブレークポイント | レイアウト |
|---|---|
| md以上(768px〜) | 現在の実装のまま。右寄せ・縦積み・幅34rem |
| md未満(〜767px) | 画面下部に固定。全幅寄り・縦積み |

## 実装アプローチ

### 原則

- PC用の inline style(top / right / width 等)は**削除しない**
- SP用のスタイルは**追加**する形で実装する
- 各パネルは自己完結した幅を持つ(親依存の `width: 100%` を避ける)
- fixed 要素の位置指定プロパティ自体を `auto` にしない
  (値を clamp() で可変にするのは可)

### 推奨する実装手段

以下のいずれかを選択してください。判断は実装者に委ねます。

**手段A: useMediaQuery で分岐**
JSでビューポート幅を判定し、PC用/SP用のstyleオブジェクトを出し分ける。

**手段B: Tailwind のレスポンシブクラス**
既存の inline style は残しつつ、
Tailwind のクラスで md未満のスタイルを上書きする。
※ inline style は Tailwind より優先度が高いため、
　この方法を採る場合は inline style から
　位置指定を Tailwind クラスへ移す必要がある。
　その際は**必ず md: プレフィックス付きで PC用も同時に指定**すること。

**手段C: CSS Modules / グローバルCSS + メディアクエリ**
外部CSSで管理する。
※ 前回の失敗はこの方法で位置指定を移管した際に発生した。
　採用する場合は、CSSが確実に適用されているか
　開発者ツールで computed style を確認すること。

### 数値要件

| 項目 | 要件 |
|---|---|
| パネル幅 | 画面幅の88〜92%程度 |
| 左右位置 | 中央揃え、または右寄せ+左右余白 |
| 下端余白 | 16px以上 |
| 2パネル合計高さ | 画面高さの55%以内 |
| フォントサイズ | clamp() で可変。最小14px以上 |
| タブの高さ | タップしやすい44px以上 |

### 内容の圧縮

SPでは高さが限られるため、以下を検討:
- エリア情報の説明文を line-clamp で行数制限
- スライダー内の画像を小さくする、または縦積みに変更
- 余白を PC より詰める
