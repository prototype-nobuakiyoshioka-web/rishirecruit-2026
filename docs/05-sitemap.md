# サイトマップ・情報設計

**Document version:** 1.0
**作成日:** 2026-05-20
**プロジェクト:** リシリクルート（rishirecruit.com）

---

## 1. 概要

本ドキュメントはリシリクルートの全ページ構成・URL設計・ナビゲーション設計・CTA配置戦略を定義する。

**設計原則:**
- 求人応募（KPI）への動線を最短かつ自然にする
- 移住検討者・求職者・一般読者・観光客の4ターゲットに対し、各々の入口を確保
- 3Dマップを主要ナビゲーションとしつつ、リスト・SEO経由の動線も並列で持つ
- グローバルCTAボタンに頼らず、各ページの文脈に応じたCTA配置で応募意欲を醸成する

## 3. 各ページの役割

### 3.1 Content（CPT駆動コンテンツ）

#### `/` Home
- 3Dマップを主要UIとしたヒーロー
- 求人ピン（コーラル）が最も目立つ表示
- Note記事の掲示板UIを配置
- スクロールで「最新の求人」「次回イベント」等の補助ナビ
- 副次CTA: 「リストで求人を見る →」(/jobs) を控えめに

#### `/jobs` 求人一覧
- カードグリッド形式
- フィルタ: 雇用形態・勤務地クラスタ（pin_location）
- 各カードに「詳細を見る →」リンク
- 全求人19件想定（v1）

#### `/jobs/[slug]` 求人詳細
- **応募動線の中核ページ**
- ACFフィールド全展開（業務内容・条件・待遇・応募フロー等）
- **画面下部 or サイドバーに固定CTA [応募する]**（スティッキー）
- CTAクリック → `/apply?job=[slug]` へ遷移
- 関連求人カードを末尾に

#### `/spots` 観光地一覧
- カードグリッド形式
- フィルタ: カテゴリ（自然・温泉・グルメ等）
- 末尾に「この島で働く → /jobs」リンク

#### `/spots/[slug]` 観光地詳細
- ヒーロー画像/動画
- アクセス情報・営業時間等のACFフィールド展開
- ギャラリー画像
- 「現在募集中の求人を見る →」を末尾に

#### `/events` イベント一覧
- カードグリッド形式
- デフォルト表示: 開催中・開催予定のみ（`end_datetime >= now` でフィルタ）
- 切替: 「過去のイベント」タブ（アーカイブ閲覧）
- カテゴリフィルタ

#### `/events/[slug]` イベント詳細
- 日時・会場・主催の明示
- 申込URLがあれば外部リンク
- 末尾に「求人一覧 →」リンク

### 3.2 Story（読む・触れる）

#### `/columns` コラム一覧
- **Note.com のRSSフィードを取得して掲示板UIで表示**
- 各記事カード: サムネイル・タイトル・投稿日・抜粋
- クリック → `target="_blank"` でnote.comの元記事へ
- 「もっと見る →」でnote.com 執筆者トップへ
- ISRで1時間ごとに再生成
- 詳細仕様は `03-content-schema.md` §6 参照

#### `/message` 町からの便り
- 町長・役場からのメッセージページ
- 「利尻富士町はこういうところで行政職員を募集しています」のトーン
- 移住検討者の感情に訴える内容
- 信頼性・想いの伝達が主目的
- 文末に「現在募集中の求人を見る →」CTA

**`/about` ではなく `/message` にした理由:**
1. コンテンツの性格と完全一致（「あなたに語りかける」内容）
2. `/about` は退屈な定型ページに見えがち
3. 「ポップ × 信頼」のブランドトーンと合致
4. 機械的・事務的な求人サイトとの差別化

ヘッダーラベルは英字`Message` / 日本語「町からの便り」を推奨。

### 3.3 Action（動く・送る）

#### `/apply` 応募意向フォーム
- URL: `/apply?job=[slug]` でクエリパラメータ経由で求人を保持
- 求人情報がページ上部に自動表示される
- 応募者情報入力に集中できるUI
- フォーム項目:
  1. お名前（必須）
  2. メールアドレス（必須）
  3. 電話番号（必須）
  4. 現在のお住まい（都道府県・必須）
  5. 現在のご職業（任意）
  6. 応募動機・自己紹介（任意・テキストエリア）
  7. ご質問・補足事項（任意）
  8. プライバシーポリシー同意（必須）
- 送信ボタン: 「応募意向を送る」
- バリデーション: クライアント + サーバー両方

#### `/apply/thanks` 応募完了
- 完了メッセージ
- 「3営業日以内に役場担当者からご連絡します」等の次ステップ案内
- 関連リンク: 「他の求人を見る」「町からの便り」
- GA/分析イベント発火ポイント（KPI計測）

#### `/contact` お問い合わせ
- 一般問い合わせ用フォーム
- 求人についても問い合わせ可能（応募ではない確認用）
- お問い合わせ理由（選択式）:
  - 求人について（応募はまだ）
  - 移住・暮らしについて
  - サイト・取材について
  - その他
- フォーム項目:
  1. お問い合わせ内容（選択式・必須）
  2. お名前（必須）
  3. メールアドレス（必須）
  4. お問い合わせ詳細（必須・テキストエリア）
  5. プライバシーポリシー同意（必須）

### 3.4 Legal & External

#### `/privacy` プライバシーポリシー
- フォーム保持があるため法的必須
- 個人情報の取得目的・利用範囲・保管期間
- お問い合わせ先

#### `/terms` 利用規約
- 任意だが推奨
- サイト利用上の注意事項

#### Note.com（外部）
- 別メンバーによるコラム執筆場所
- RSS経由でリシリクルート側の `/columns` に表示
- 元記事の表示は note.com 上のみ（リシリクルート側はDB保存しない）

## 4. URL命名規則

| 種別 | パターン | 例 |
|---|---|---|
| 一覧 | 複数形（英語） | `/jobs`, `/spots`, `/events`, `/columns` |
| 詳細 | 一覧 + slug | `/jobs/honchou-jimu-2026` |
| シングル | 単数形（短く） | `/message`, `/contact`, `/apply` |
| アクション後 | アクション + サブ | `/apply/thanks` |
| 法的 | 短い名詞 | `/privacy`, `/terms` |

**ルール:**
- 全小文字
- ハイフン区切り（アンダースコア不可）
- 日本語URL不可（英語化必須）
- 末尾スラッシュなし
- クエリパラメータは `?key=value` 形式（例: `/apply?job=slug`）

**slug命名（job_posting等の詳細ページ用）:**
- 英小文字 + ハイフン + 数字のみ
- 例: `honchou-jimu-2026`, `hokenshi-2026`, `airport-staff-2026`
- 一度公開したらslugは原則変更しない（リンク切れ防止）

## 5. ヘッダーナビゲーション

### 5.1 デスクトップ表示

```
[ロゴ]   求人  ·  観光地  ·  イベント  ·  コラム  ·  町からの便り
```

| ラベル | リンク先 | 役割 |
|---|---|---|
| ロゴ | `/` | ホームへ戻る |
| 求人 | `/jobs` | KPI直結 |
| 観光地 | `/spots` | ライフスタイル想起 |
| イベント | `/events` | 季節感・活気 |
| コラム | `/columns` | 物語・人柄の伝達 |
| 町からの便り | `/message` | 信頼・想いの伝達 |

**重要: グローバルCTAボタンは設置しない。** トップページにある「応募する」ボタンの遷移先が定まらないため。CTAは各ページの文脈に応じて配置する（§7参照）。

### 5.2 モバイル表示

- ハンバーガーメニュー（右上）
- タップで全項目の一覧オーバーレイ表示
- ハンバーガーアイコンは深海ブルー（#0A2E4E）

### 5.3 ヘッダーのスタイル

- 高さ: 64px（デスクトップ）/ 56px（モバイル）
- 背景: 暖白 #FAF6EE（半透明 + ブラー） or 純白
- スクロール時: 固定（sticky）
- アクティブページのラベル: 下線 or 色変更

## 7. CTA配置戦略

ヘッダーに固定CTAを置かず、**各ページの文脈に応じてCTAを配置**する。

| ページ | 主要CTA | 副次CTA・リンク |
|---|---|---|
| `/` Home | 3Dマップの**ピン**そのものがCTA | 「リストで求人を見る →」(/jobs) |
| `/jobs` | 各求人カードの「詳細を見る →」 | — |
| **`/jobs/[slug]`** | **固定CTA [応募する]**（スティッキー） | 「他の求人を見る」「お問い合わせ」 |
| `/spots`, `/spots/[slug]` | — | 「この近くの求人 →」(/jobs) |
| `/events`, `/events/[slug]` | — | 「求人一覧 →」 |
| `/columns` | — | 「求人を見る →」を末尾に |
| `/message` | — | 「現在募集中の求人を見る →」を末尾に |
| `/contact` | フォーム送信ボタン | — |
| `/apply` | フォーム送信ボタン「応募意向を送る」 | — |
| `/apply/thanks` | 「他の求人を見る」 | 「町からの便り」 |
| 法的ページ | — | — |

### 7.1 求人詳細ページの固定CTA仕様

- **形状**: 画面下部に常時表示される横長バー（モバイル）/ 右サイドバーに固定（デスクトップ）
- **色**: 夕陽コーラル（#FF7B5B）背景・白文字
- **テキスト**: 「応募する」
- **挙動**: クリックで `/apply?job=[slug]` へ遷移
- **スクロール時**: 常に表示（fixed/sticky）
- **モバイル**: 親指届きやすい下部固定
- **アクセシビリティ**: `aria-label` 設定、フォーカス可能、十分なタップ領域（44×44px以上）

## 10. SEO考慮事項

### 10.1 必須メタデータ（各ページ）

- `<title>` ページ固有のタイトル
- `<meta name="description">` 150文字以内
- `<meta property="og:image">` シェア用画像
- `<meta property="og:type">` website / article
- `<link rel="canonical">` 重複防止

### 10.2 構造化データ（JSON-LD）

| ページ | スキーマ |
|---|---|
| `/jobs/[slug]` | JobPosting |
| `/events/[slug]` | Event |
| `/spots/[slug]` | TouristAttraction |
| `/message` | Organization or Article |
| `/` | WebSite |

### 10.3 XMLサイトマップ

- `/sitemap.xml` を自動生成
- WordPress (WPGraphQL) から全公開コンテンツのslugを取得
- 1日1回再生成（ISR）

### 10.4 robots.txt

```
User-agent: *
Allow: /

Sitemap: https://rishirecruit.com/sitemap.xml
```

### 10.5 canonical URL

- 求人モーダル（3Dマップから開く）と求人詳細ページ（/jobs/[slug]）が同じコンテンツを持つため、両方のメタタグで `/jobs/[slug]` をcanonicalに指定

## 11. アクセシビリティ考慮

- 3Dマップが操作できないユーザー向けに、必ず `/jobs` 等のリスト経由のアクセス手段を確保
- すべてのインタラクティブ要素にキーボード操作可能
- 色だけで情報を伝えない（ピン色 + アイコン形状の併用）
- スクリーンリーダー対応のためのaria属性
- フォームバリデーションメッセージは視覚 + 文章で伝達

---

## 12. パンくずリスト

各詳細ページに配置:

```
ホーム > 求人 > 主事補（一般事務）
ホーム > 観光地 > 姫沼
ホーム > イベント > 鬼脇まつり
```

シングルページ（/message, /contact等）には不要。
