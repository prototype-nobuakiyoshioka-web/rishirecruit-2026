# サイトマップ・情報設計

**Document version:** 2.0
**作成日:** 2026-06-19
**プロジェクト:** リシリクルート(rishirecruit.com)

---

## 1. 概要

本ドキュメントはリシリクルートの全ページ構成・URL設計・ナビゲーション設計・CTA配置戦略を定義する。

**設計原則:**
- 求人応募(KPI)への動線を最短かつ自然にする
- 移住検討者・求職者・一般読者・観光客の4ターゲットに対し、各々の入口を確保
- 3Dマップを主要ナビゲーションとしつつ、リスト・SEO経由の動線も並列で持つ
- グローバルCTAボタンに頼らず、各ページの文脈に応じたCTA配置で応募意欲を醸成する
- **3D Canvas の上に重なる「HUD(Heads-Up Display)」レイヤー**を持つ。ヘッダーや常駐オブジェクトはこのレイヤーに属し、3Dの回転・スクロールと独立して画面に固定表示される

### 1.1 v2 での変更点

- ヘッダーナビゲーションを5項目から**6項目**に変更(「コラム」を外し、「移住者の声」「お問い合わせ」を追加)
- **「移住者の声」を新規CPT `testimonial` として追加**(`/voices`)
- 「コラム」はヘッダーから外れ、**3D Canvas 上に常時表示される「コラム看板」**(HUD要素)からの導線に変更
- 「お問い合わせ」をフッターからヘッダーへ昇格(問い合わせの間口拡大)

## 3. 各ページの役割

### 3.1 Content(CPT駆動コンテンツ)

#### `/` Home

- 3Dマップを主要UIとしたヒーロー
- 求人ピン(コーラル)が最も目立つ表示
- 画面左下に「コラム看板」(HUD要素)を常時表示(詳細は5.4)
- ヘッダー(HUD要素)を画面上部に常時表示
- スクロールで「最新の求人」「次回イベント」等の補助ナビ
- 副次CTA: 「リストで求人を見る →」(/jobs) を控えめに

#### `/jobs` 求人一覧

- カードグリッド形式
- フィルタ: 雇用形態・勤務地クラスタ(pin_location)
- 各カードに「詳細を見る →」リンク

#### `/jobs/[slug]` 求人詳細

- 応募動線の中核ページ
- ACFフィールド全展開(業務内容・条件・待遇・応募フロー等)
- 画面下部 or サイドバーに固定CTA [応募する](スティッキー)
- CTAクリック → `/apply?job=[slug]` へ遷移
- 関連求人カードを末尾に
- (任意)関連する testimonial があれば「先輩職員の声」セクションを表示

#### `/spots` 観光地一覧

- カードグリッド形式
- フィルタ: カテゴリ(自然・温泉・グルメ等)
- 末尾に「この島で働く → /jobs」リンク

#### `/spots/[slug]` 観光地詳細

- ヒーロー画像/動画
- アクセス情報・営業時間等のACFフィールド展開
- ギャラリー画像
- 「現在募集中の求人を見る →」を末尾に

#### `/events` イベント一覧

- カードグリッド形式
- デフォルト表示: 開催中・開催予定のみ(end_datetime >= now でフィルタ)
- 切替: 「過去のイベント」タブ(アーカイブ閲覧)
- カテゴリフィルタ

#### `/events/[slug]` イベント詳細

- 日時・会場・主催の明示
- 申込URLがあれば外部リンク
- 末尾に「求人一覧 →」リンク

#### `/voices` 移住者の声 一覧(New)

- カードグリッド形式
- 各カード: メイン写真・キャッチコピー・移住年
- ピンを持たない(3D地図には出ない、一覧ページのみ)
- 末尾に「現在募集中の求人を見る →」を末尾に

#### `/voices/[slug]` 移住者の声 詳細(New)

- メイン写真 + 移住前/移住後プロフィール
- リード文(編集側の導入要約)
- インタビュー本文(自由記述、写真込み可)
- (任意)関連求人カードを表示(related_job が設定されている場合)
- 末尾に「関連する求人を見る →」または「求人一覧 →」

詳細仕様は03-content-schema.md 6章(testimonial CPT)参照。

### 3.2 Story(読む・触れる)

#### `/columns` コラム一覧

- Note.com のRSSフィードを取得して掲示板UIで表示
- 各記事カード: サムネイル・タイトル・投稿日・抜粋
- クリック → target="_blank" でnote.comの元記事へ
- 「もっと見る →」でnote.com 執筆者トップへ
- ISRで1時間ごとに再生成
- 詳細仕様は03-content-schema.md 7章参照

#### `/message` 町からの便り

- 町長・役場からのメッセージページ
- 「利尻富士町はこういうところで行政職員を募集しています」のトーン
- 移住検討者の感情に訴える内容
- 信頼性・想いの伝達が主目的
- 文末に「現在募集中の求人を見る →」CTA

`/about` ではなく `/message` にした理由:

1. コンテンツの性格と完全一致(「あなたに語りかける」内容)
2. /about は退屈な定型ページに見えがち
3. 「ポップ × 信頼」のブランドトーンと合致
4. 機械的・事務的な求人サイトとの差別化

ヘッダーラベルは英字Message / 日本語「メッセージ」を採用(v2でラベル変更、旧「町からの便り」)。

### 3.3 Action(動く・送る)

#### `/apply` 応募意向フォーム

- URL: `/apply?job=[slug]` でクエリパラメータ経由で求人を保持
- 求人情報がページ上部に自動表示される
- 応募者情報入力に集中できるUI
- フォーム項目:
  1. お名前(必須)
  2. メールアドレス(必須)
  3. 電話番号(必須)
  4. 現在のお住まい(都道府県・必須)
  5. 現在のご職業(任意)
  6. 応募動機・自己紹介(任意・テキストエリア)
  7. ご質問・補足事項(任意)
  8. プライバシーポリシー同意(必須)
- 送信ボタン: 「応募意向を送る」
- バリデーション: クライアント + サーバー両方

#### `/apply/thanks` 応募完了

- 完了メッセージ
- 「3営業日以内に役場担当者からご連絡します」等の次ステップ案内
- 関連リンク: 「他の求人を見る」「町からの便り」
- GA/分析イベント発火ポイント(KPI計測)

#### `/contact` お問い合わせ

- 一般問い合わせ用フォーム
- 求人についても問い合わせ可能(応募ではない確認用)
- お問い合わせ理由(選択式): 求人について(応募はまだ) / 移住・暮らしについて / サイト・取材について / その他
- フォーム項目:
  1. お問い合わせ内容(選択式・必須)
  2. お名前(必須)
  3. メールアドレス(必須)
  4. お問い合わせ詳細(必須・テキストエリア)
  5. プライバシーポリシー同意(必須)

### 3.4 Legal & External

#### `/privacy` プライバシーポリシー

- フォーム保持があるため法的必須
- 個人情報の取得目的・利用範囲・保管期間
- お問い合わせ先

#### `/terms` 利用規約

- 任意だが推奨
- サイト利用上の注意事項

#### Note.com(外部)

- 別メンバーによるコラム執筆場所
- RSS経由でリシリクルート側の /columns に表示
- 元記事の表示は note.com 上のみ(リシリクルート側はDB保存しない)

## 4. URL命名規則

| 種別 | パターン | 例 |
|---|---|---|
| 一覧 | 複数形(英語) | /jobs, /spots, /events, /voices, /columns |
| 詳細 | 一覧 + slug | /jobs/honchou-jimu-2026 |
| シングル | 単数形(短く) | /message, /contact, /apply |
| アクション後 | アクション + サブ | /apply/thanks |
| 法的 | 短い名詞 | /privacy, /terms |

ルール:

- 全小文字
- ハイフン区切り(アンダースコア不可)
- 日本語URL不可(英語化必須)
- 末尾スラッシュなし
- クエリパラメータは ?key=value 形式(例: /apply?job=slug)

slug命名(job_posting等の詳細ページ用):

- 英小文字 + ハイフン + 数字のみ
- 例: honchou-jimu-2026, hokenshi-2026, airport-staff-2026
- 一度公開したslugは原則変更しない(リンク切れ防止)

## 5. HUDレイヤー設計(3D Canvas の上に重なるUI)

v2 で新設したセクション。3D島の回転・スクロールに関係なく、画面に固定表示される要素群を扱う。

### 5.1 HUDレイヤーの構成要素

模式図(画面イメージ):

```
ヘッダー(カプセル型ナビ、6項目)          ← HUD固定(常時)

       [3D島・山・ピン]                  ← Canvas(スクロール連動回転)

[コラム看板]          [ピン詳細パネル]    ← HUD固定 / イベント駆動
```

| 要素 | 表示 | 3Dとの連動 |
|---|---|---|
| ヘッダー | 常時(全ページ) | 連動しない、画面上部に固定 |
| コラム看板 | 常時(トップページのみ) | 連動しない、画面左下に固定 |
| ピン詳細パネル | ピンクリック時のみ | ピンの位置に応じて表示、ただし画面に対して固定パネル |

### 5.2 デスクトップ表示(ヘッダー)

レイアウトイメージ: [ロゴ] メッセージ / 移住者の声 / 求人 / 観光地 / イベント / お問い合わせ

| ラベル | リンク先 | 役割 |
|---|---|---|
| ロゴ | / | ホームへ戻る |
| メッセージ | /message | 信頼・想いの伝達 |
| 移住者の声 | /voices | リアルな移住事例の提示 |
| 求人 | /jobs | KPI直結 |
| 観光地 | /spots | ライフスタイル想起 |
| イベント | /events | 季節感・活気 |
| お問い合わせ | /contact | 間口拡大(自治体・取材等の受け皿) |

「コラム」はヘッダーに含まれない。3D Canvas 上の「コラム看板」(5.4節)が導線を担う。

「お問い合わせ」をヘッダーに昇格した理由(v1からの変更):

- 求人応募以外の問い合わせ(自治体連携・取材・移住相談等)の間口を広げたい
- 1人運営のため、様々な経路からの接触を逃さず拾う必要がある

### 5.3 モバイル表示

- ハンバーガーメニュー(右上)
- タップで6項目の一覧オーバーレイ表示
- ハンバーガーアイコンは深海ブルー(#0A2E4E)

### 5.4 コラム看板(HUD要素・新設)

「コラム」への導線を、ヘッダーのテキストリンクではなく、3D空間に浮かぶゲームライクなUIオブジェクトとして表現する。

| 項目 | 仕様 |
|---|---|
| レイヤー | DOM UIレイヤー(3D Canvasの上に固定オーバーレイ、3Dシーンの一部ではない) |
| 表示位置 | 画面左下 |
| 表示タイミング | トップページ(/)訪問時、常時表示 |
| 見た目 | 木製看板風のイラスト + テキスト「コラム(NOTE)」 |
| スクロール・回転への追従 | しない(3D側の回転・スクロールと完全に独立、画面に対して固定) |
| クリック時の遷移 | /columns 一覧ページへ |
| 表示ページ | トップページ(/)のみ。他ページには出さない |

この設計により、ヘッダーの項目数を6つに抑えつつ、コラムへの個性的な導線を確保する。求人ピン・観光地ピン・イベントピンと並ぶ「第4の入口」だが、ピンではなく独自オブジェクトとして扱う。

### 5.5 ヘッダーのスタイル

- 高さ: 64px(デスクトップ)/ 56px(モバイル)
- 背景: 暖白 #FAF6EE(半透明 + ブラー)or 純白、カプセル型(角丸full)
- スクロール時: 固定(sticky)
- アクティブページのラベル: 下線 or 色変更

## 7. CTA配置戦略

ヘッダーに固定CTAを置かず、各ページの文脈に応じてCTAを配置する。

| ページ | 主要CTA | 副次CTA・リンク |
|---|---|---|
| / Home | 3Dマップのピンそのものが CTA | 「リストで求人を見る →」(/jobs)、コラム看板(/columns) |
| /jobs | 各求人カードの「詳細を見る →」 | — |
| /jobs/[slug] | 固定CTA [応募する](スティッキー) | 「他の求人を見る」「お問い合わせ」 |
| /spots, /spots/[slug] | — | 「この近くの求人 →」(/jobs) |
| /events, /events/[slug] | — | 「求人一覧 →」 |
| /voices | — | 「現在募集中の求人を見る →」 |
| /voices/[slug] | — | (任意)「関連する求人を見る →」、なければ「求人一覧 →」 |
| /columns | — | 「求人を見る →」を末尾に |
| /message | — | 「現在募集中の求人を見る →」を末尾に |
| /contact | フォーム送信ボタン | — |
| /apply | フォーム送信ボタン「応募意向を送る」 | — |
| /apply/thanks | 「他の求人を見る」 | 「町からの便り」 |
| 法的ページ | — | — |

### 7.1 求人詳細ページの固定CTA仕様

- 形状: 画面下部に常時表示される横長バー(モバイル)/ 右サイドバーに固定(デスクトップ)
- 色: 夕陽コーラル(#FF7B5B)背景・白文字
- テキスト: 「応募する」
- 挙動: クリックで /apply?job=[slug] へ遷移
- スクロール時: 常に表示(fixed/sticky)
- モバイル: 親指届きやすい下部固定
- アクセシビリティ: aria-label 設定、フォーカス可能、十分なタップ領域(44×44px以上)

## 8. コンバージョン動線

### 8.1 メインフロー(KPI最重要パス)

Home(/)→ 3D島上の求人ピンをクリック → 求人モーダル(プレビュー)→ 「詳細を見る」リンク → /jobs/[slug](詳細ページ)→ 固定CTA「応募する」→ /apply?job=[slug] → フォーム送信 → /apply/thanks → 計測イベント発火

### 8.2 サブフロー1: 一覧経由

Home(/)→ ヘッダー「求人」or 副次CTA「リストで見る」→ /jobs(一覧)→ カードクリック → /jobs/[slug](詳細)→ 以下メインフローと同じ

### 8.3 サブフロー2: コラム看板経由

Home(/)→ 画面左下のコラム看板をクリック → /columns(コラム一覧)→ 興味喚起 → 末尾CTA「求人を見る」→ /jobs(一覧)→ 以下メインフローと同じ

### 8.4 サブフロー3: 移住者の声経由(新設)

Home(/)or ヘッダー「移住者の声」→ /voices(一覧)→ カードクリック → /voices/[slug](詳細)→ 関連求人カード or 「求人一覧」リンク → /jobs または /jobs/[slug] → 以下メインフローと同じ

### 8.5 サブフロー4: メッセージ経由(移住検討者向け)

ヘッダー「メッセージ」→ /message(町からの便り)→ 末尾CTA「求人を見る」→ /jobs(一覧)→ 以下メインフローと同じ

### 8.6 サブフロー5: 外部からの直接流入

SNS・検索エンジン → SEO・シェアリンク → /jobs/[slug](詳細・ディープリンク)→ 固定CTAから直接 → /apply?job=[slug] → 以下メインフロー

### 8.7 サブフロー6: お問い合わせ経由

ヘッダー「お問い合わせ」→ /contact → 送信 → お問い合わせ完了 →(メール返信で求人案内可能)

## 10. SEO考慮事項

### 10.1 必須メタデータ(各ページ)

- title: ページ固有のタイトル
- meta description: 150文字以内
- og:image: シェア用画像
- og:type: website / article
- canonical: 重複防止

### 10.2 構造化データ(JSON-LD)

| ページ | スキーマ |
|---|---|
| /jobs/[slug] | JobPosting |
| /events/[slug] | Event |
| /spots/[slug] | TouristAttraction |
| /voices/[slug] | Article または Person(検討中) |
| /message | Organization または Article |
| / | WebSite |

### 10.3 XMLサイトマップ

- /sitemap.xml を自動生成
- WordPress(WPGraphQL)から全公開コンテンツのslugを取得(job_posting, touristspot, event, testimonial)
- 1日1回再生成(ISR)

### 10.4 robots.txt

User-agent: * / Allow: / / Sitemap: https://rishirecruit.com/sitemap.xml

### 10.5 canonical URL

求人モーダル(3Dマップから開く)と求人詳細ページ(/jobs/[slug])が同じコンテンツを持つため、両方のメタタグで /jobs/[slug] をcanonicalに指定

## 11. アクセシビリティ考慮

- 3Dマップが操作できないユーザー向けに、必ず /jobs 等のリスト経由のアクセス手段を確保
- すべてのインタラクティブ要素にキーボード操作可能
- 色だけで情報を伝えない(ピン色 + アイコン形状の併用)
- コラム看板等のHUD要素もキーボード操作・スクリーンリーダー対応(tabindex, aria-label)
- スクリーンリーダー対応のためのaria属性
- フォームバリデーションメッセージは視覚 + 文章で伝達
